========================================================

- CesiumMan test generates USD content with correct asset path: @./textures/Default_albedo.jpg@
- However, the actual texture file is NOT extracted to filesystem for USDA export
- Other tests in /basic directory successfully create textures/ folders

CURRENT CODE ANALYSIS:

1. ExportTextures() method (line 794):
   - Currently just logs "Texture processing delegated to material handlers"
   - No actual texture file extraction happening

2. HandleEmbeddedTexture() method (line 2795):
   - Sets uvTexture.file asset path to "./textures/filename"
   - Does NOT write texture data to disk
   - Only generates the USD reference path

3. HandleExternalTexture() method (line 2860):
   - Sets uvTexture.file asset path to "./textures/filename" 
   - Does NOT copy external texture files to textures directory

4. SaveAsUSDA() method (line 3867):
   - Only saves the main USDA file using tinyusdz::usda::SaveAsUSDA()
   - Comment mentions textures should be "manually copied to textures/ subdirectory if needed"
   - This manual copying is never implemented!

5. CollectTextureDataForUSDZ() method (line 3983):
   - Only used for USDZ export (embedded in zip)
   - Collects texture data but doesn't write to filesystem

ROOT CAUSE:
For USDA export, the code sets asset paths in USD content but never actually:
1. Creates the textures/ directory
2. Writes embedded texture data to files
3. Copies external texture files

SOLUTION PLAN:
1. Update unit test to verify textures directory exists
2. Implement texture file extraction in SaveAsUSDA()
3. Create ExtractTexturesForUSDA() method to handle both embedded and external textures
4. Ensure directory creation happens before file writing
